# T2.1 候选点生成与覆盖数据

从合并了 PR #2～#4 的 `main` 建分支。用该基线的 `geometry.py`、`coverage.py` 和 `simulate.py` 塔参数生成候选点。环境、提交、文件哈希、实测计时和逐项检查见 `T2.1.json`，分布与过滤统计见 `results/t2.1/summary.json`。

| 来源 | 采样规则 |
|---|---|
| 顶点环带 | 七个顶点，半径 15、30、50、75、100、125、150、200 m，每隔 15° 采样 |
| 沿路径法线 | 每段按最多 20 m 沿程间距等分，在非端点的两侧法线上偏移 15、25、40、60、90、120、160、190 m |
| 100 m 网格 | 以地图原点为锚点，覆盖含边界的地图方形 |

按塔心范围 `[10,1990]×[10,1990]`、到折线中心线距离 `≥15 m` 顺序硬过滤。三类塔型分别计算覆盖区间和总弧长。去重按大、中、小塔覆盖弧长依次降序；覆盖相同的点按坐标及来源排序。若某点和已保留点距离严格小于 20 m，则剔除该点。无覆盖点保留在有限候选集，覆盖矩阵中相应为零。采样与去重规则是本次工程取值，选址结论限于保留的有限点集。

以 20 m/s 匀速计算单塔对单只敌人的理论伤害 `覆盖弧长 / 20 × DPS`。实际多敌结果由仿真确认。

## 数据接口

`candidates.csv` 每个候选点一行，依次给出 ID、米制坐标、来源、距路距离，以及小、中、大塔各自的覆盖弧长和理论伤害。CSV 与 NPZ 的点顺序一致。

`candidates.npz` 可使用 `numpy.load(path, allow_pickle=False)` 读取：

| 键 | 形状与含义 |
|---|---|
| `ids`, `sources`, `distance_to_road_m` | `(N,)`，候选 ID 从 1 开始，来源编码为 `vertex_ring`、`path_normal`、`grid_100m` |
| `xy_m` | `(N, 2)`，塔心坐标 |
| `tower_types` | `(3,)`，列序为小塔、中塔、大塔 |
| `coverage_m`, `damage_hp` | `(N, 3)`，每点每塔型的覆盖长度和单敌理论伤害 |
| `interval_offsets`, `intervals_m` | `(3N+1,)` 和 `(K,2)`。零基点行 `i`、塔型列 `j` 对应 `k=3*i+j`，取 `intervals_m[interval_offsets[k]:interval_offsets[k+1]]` 得闭弧长区间 |

T2.2 可以按候选 ID 与塔型列接入覆盖矩阵，保存不同区间的弧长边界供建模使用。目标顺序沿用队长裁定，先最小漏怪，再最大剩余资金。求解器等 Hermes 的 ILP 框架到手后再实现。
